### 4.1 Workflow do round (estabelecido desde Round 4)

1. **Pré-codar:** mapear estrutura, propor plano em 5-10 linhas, listar 6-8 perguntas críticas. **Não codar até confirmar.**
2. Branch nova de `main` (atualizado pós-merge do PR anterior).
3. Implementação em chunks com commits atômicos.
4. Validação: `ruff check notion_rpadv notion_bulk_edit && python -m compileall -q notion_rpadv notion_bulk_edit && python -m pytest tests/ -q`.
5. Reportar pra usuário com sumário detalhado, mensagens de commit ricas, e **aguardar autorização explícita pra push.**
6. Push.
7. Usuário cria PR + merge no GitHub web (`gh` CLI **não está instalado** — não tente `gh pr create`).
8. Cleanup local pós-merge (opcional).

### 4.2 Padrão de commit

- Trailer obrigatório: `Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>`
- Multi-paragráfico (5-30 linhas), prefixo convencional (`feat:`, `fix:`, `chore:`, `refactor:`, `docs:`, `perf:`)
- Heredoc `cat <<'EOF' ... EOF` em bash pra preservar formatação
- Mensagem explica **o que** mudou, **por que** (root cause/uso/spec), **como** (arquiteturalmente), e **validação** (testes/coverage)

### 4.3 Padrão de tests

- pytest, sem outras frameworks
- Testes Qt usam `QApplication.instance() or QApplication(sys.argv)` no início
- Mocks via `unittest.mock` (sem rede/Qt em testes puros)
- Conftest popula `SchemaRegistry` singleton com fixtures de `tests/fixtures/schemas/*.json`
- Coverage só foi medida formalmente nos rounds onde havia exigência (R7: `dje_transform` = 100%, `dje_client` = 98%, `dje_exporter` = 100%)
- Use `python -m coverage` (não `pytest-cov`) — `coverage` está instalado, `pytest-cov` não

- Não modificar testes existentes pra fazê-los passar (testes são oráculo); rebatizar quando o contrato muda é OK e documentar no commit.
- Sem novas dependências sem autorização.
- Sem mudanças que quebrem API pública.
- pt-BR direto na UI e mensagens visíveis ao usuário; variáveis e commit messages podem ser em inglês.
